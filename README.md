# 卡拉彼丘 QQ 机器人插件（Celestia）

在 QQ 群聊中直接发送指令，查询《卡拉彼丘》的战绩、排行榜、游戏资料与福利信息，全部以图片返回。

* **框架**：[Kokona](https://github.com/szzz666/Kokona)（Java 21 / OneBot 11）
* **数据来源**：Dakanu（战绩）+  biligame 卡拉彼丘 WIKI（资料）
* **触发方式**：群聊直接发送，无需 @机器人

---

## 快速开始

```bash
./build.sh          # 输出 build/Celestia.jar
```

把 jar 放进 Kokona 的 `plugins/` 目录并重启即可。需要 JDK 21+，**无需安装任何字体或图片库**（相关依赖已内置）。

首次运行会在 `plugins/Celestia/` 生成配置文件与素材缓存。

## 指令与帮助图的一致性

`config.yml` 中有 11 条指令配置，帮助图（`帮助`）逐条列出这 11 条，一一对应。

**别名会完整显示**。8 条指令配了别名，帮助图上以灰色小字跟在主名后：

```
兑换码  cdk / 礼包码
武器数据  ttk / dps
个性名片  名片
```

**别名从配置动态读取**，不是写死在图片里。改完 `config.yml` 重启后，
帮助图会显示新的别名——可以加 `gift`、`兑换` 这样的自定义别名，图上立刻能看到。

---

> **图鉴与资料类内容没有独立指令**。勋章、喷漆、头像框、基板、个性名片、核心、
> 地图、角色、武器、角色定位、战斗模式、武器数据、信用分、活动、赛季
> 全部通过「菜单」逐层进入，或用 `wiki <页面名>` 查询。

## 数据新鲜度

站点并非实时同步：它对每个玩家独立抓取，实测有的数据滞后 **10-16 天**。
这不是本插件缓存造成的，而是站点自身的抓取策略。

### 两个指令

```
看看米雪儿        → 读缓存，约 2 秒返回；卡片标注数据抓取时间
看看最新米雪儿    → 请求站点重新抓取，约 10-40 秒，保证最新
```

两条是独立指令，`看看最新` 不会和 `看看` 抢前缀（命令名按长度从长到短匹配）。

默认走缓存是有原因的：**站点刷新接口实测成功率仅约 1/3**（其余返回 524 超时）。
如果每次查询都强制刷新，大部分请求都要白等半分钟才能拿到图。

### 刷新失败的处理

| 情况 | 处理 |
| :--- | :--- |
| 刷新成功 | 出最新数据的图 |
| 刷新失败（524） | 提示「刷新未成功，以下为存档数据」，用缓存出图 |
| 隐私玩家 | 先查 `privacyStatus`，为 hidden 时直接说明并用存档，不让用户空等 |

**不做重试**。成功率本来就低，重试会把失败等待从 33 秒翻倍到 66 秒，收益不抵代价。

读超时设为 40 秒：成功场景实测 10-40 秒，失败时站点约 31 秒返回 524。

### 卡片标注数据时间

图右上角显示抓取时间，超过 24 小时会标「已过期」：

```
S2&EP4 · 数据抓取于 10 小时前
S2&EP4 · 数据抓取于 16 天前（已过期，非实时）
```

## 交互细节

**空格可省略** —— `看看米雪儿` 与 `看看 米雪儿` 等价。框架按空白切分命令名，插件在事件阶段补回分隔空格。

**昵称可含空格** —— `看看 浅海梦是坏女人喵` 会把指令后的内容整体当作昵称。

**对局短号** —— 对局号支持只写尾数，自动匹配最近的对局（`看看对局米雪儿774287`）。

**同名玩家选择** —— 匹配到多个同名玩家（如两个「心心子」）时列出候选，回复序号选择：

```
找到 2 个与「心心子」匹配的引航者，请回复序号：
1. 心心子  ID 6661532  Lv.320
2. 心心子  ID 6661504
回复 1 - 2 选择，回复「取消」放弃（2 分钟内有效）。
```

判定规则：只有 **多个精确匹配** 时才要求选择；若只有一个精确匹配（如「心夏」有 8 个候选但仅 1 个精确），直接出图。

## 数字交互规则

所有带序号的图都支持**直接回复数字**，不必重复指令前缀：

| 你看到的图 | 回复 | 效果 |
| :--- | :--- | :--- |
| 功能菜单 | `2` | 进入第 2 个分类 |
| BGM 曲目列表 | `165` | 点播第 165 首 |
| 壁纸网格 | `3` | 取第 3 张原图 |
| 图鉴分页 | `2` | 翻到第 2 页 |
| 同名玩家候选 | `1` | 选择第 1 个玩家 |
| 玩家卡片最近战绩 | `4` | 查看第 4 场对局详情 |

带命令的写法同样有效：`BGM 5`、`壁纸 3`、`勋章 2`。

### 数字归属的优先级

同一时刻可能有多个交互在等待数字，按此顺序判定：

```
1. 同名玩家选择   用户刚查了玩家，正等着挑人
2. 菜单会话       用户正在逐层浏览
3. 卡片上下文     用户刚看了 BGM / 壁纸 / 图鉴
```

越靠前的优先级越高。例如菜单打开时，数字属于菜单，不会被之前的壁纸上下文抢走。

### 上下文生命周期

- 发新指令时自动清除（注意力已转移，旧的列表不再响应数字）
- 3 分钟无操作自动失效
- 菜单里回复「取消」时一并清除

### 最近战绩序号

「看看」的玩家卡片上，最近战绩 10 场带 1-10 序号。三种查法都行：

```
4                → 直接回数字，看第 4 场
看看对局 4       → 显式写法（带前缀，引用图片回复时也能用）
看看对局 米雪儿 784500300880910863   → 按完整对局号
```

上下文有效期 15 分钟，期间可反复回不同序号，不必重新「看看」。
按当前实现，序号取的是**最近一次**玩家卡片的列表；发新指令会清空上下文。

### 引用卡片回复

除了直接回数字，还可以**引用某张玩家卡片**再回数字，按那张卡片的序号解析：

```
引用玩家 A 的卡片 → 发 2   → 查 A 的第 2 场（哪怕之后又发过 B 的卡片）
```

实现方式：发卡片时把自身消息 ID 与该卡片的对局列表一起登记（`BotCardRegistry`），
回复时从消息的 `reply` 段取被引用消息 ID 反查。

为此给框架补了能力：OneBot 的 `send_group_msg` 回包里有 `message_id`，
但原框架发送后直接丢弃回包，插件无从得知。现在请求带 `echo` 标记，
回包按标记匹配后取出 `message_id` 回调给插件。

### 翻页

壁纸每页 15 张，共 4 页：

```
壁纸 第2页      → 跳到第 2 页
壁纸 下一页     → 下一页
壁纸 上一页     → 上一页
```

## 实现说明

### 模块结构

```

├── KokonaCelestiaMain.java      入口：注册 25 条指令
├── api/

│   ├── WikiGallery.java         图鉴条目解析（名称 + 图片）
│   └── WikiBgm.java             BGM 曲目与音频直链
├── command/
│   ├── Commands.java            基础指令实现
│   ├── WikiCommands.java        WIKI / 兑换码 / BGM
│   ├── WikiDirect.java          页面直达指令
│   ├── MenuCommands.java        菜单导航
│   ├── MenuSession.java         菜单会话（导航栈）

├── model/PlayerProfile.java     战绩数据模型
├── render/                      出图（Theme / Card / Assets / Fonts）
└── util/
    ├── Http.java                裸 TLS 客户端（IP 直连 + 空 SNI + Host 头）
    └── Reply.java               消息发送封装
```

### 几个关键技术点

**1. TLS 阻断绕过**

Dakanu 存在 TLS 握手阻断，且网关校验 Host 头（缺失返回 418）。`HttpsURLConnection` 会忽略手工设置的 Host 头，因此 [Http.java](src/main/java/top/szzz666/KokonaCelestia/util/Http.java) 基于 `SSLSocket` 手写 HTTP/1.1：连接目标为 IP、SNI 置空、Host 头显式写入域名、证书校验关闭，并按 `Content-Length` 精确读取以支持连接复用。

**2. WebP 解码内置**

头像、立绘、地图、段位徽章均为 WebP，JDK 自带 ImageIO 不支持。插件把 TwelveMonkeys 的 5 个 jar 打包进 `resources/webp/`，运行时解压并用独立 `URLClassLoader` 注册进 `IIORegistry`，**使用者无需安装依赖**。

**3. 中文字体内置**

多数 Linux 服务器没有中文字体，逻辑字体会把汉字画成方块。插件自带思源黑体（完整 CJK 基本区，压缩后约 4.3MB），粗体由 Java2D 合成以省掉第二份字体。这同时保证了**跨平台出图完全一致**——若改用系统字体，macOS 的 PingFang 与 Linux 的 Noto 字形字宽都不同。

**4. WIKI 抓取要点**

* **必须带 `Referer`**：站点启用 EdgeOne 防护，缺少该头会返回 HTTP 567
* **取 `prop=text` 而非 wikitext**：大量页面的数据来自 Lua 模块、Widget 或 SMW 查询，wikitext 里只有模板调用
* **必须 `redirects=1`**：WIKI 有大量重定向页（「好友亲密度」→「好友」）
* **表格先扁平化**：`<td>` 之间常有换行，直接转文本会把一行表格拆散

**5. 出图性能**

| 环节 | 优化前 | 优化后 | 做法 |
| :--- | ---: | ---: | :--- |
| 布局测量 | 28 s | 0 ms | 去掉「先画一遍再量高」，改为各视图精确计算 |
| 图片获取 | 25 s | 3-4 s | 磁盘缓存 + 16 并发 + 连接复用 |

磁盘缓存位于 `plugins/Celestia/assets-cache/`，素材内容固定、路径即标识，只下载一次，进程重启后复用。

| 场景 | 耗时 |
| :--- | ---: |
| 全新部署（缓存为空） | 4.7 s |
| 进程重启后（缓存命中） | 0.4 s |
| 同一玩家再次查询 | 0.11 s |

**6. 空格补全**

框架的 `CommandManage.dispatch` 用 `content.split("\\s+")` 取第一个词作为命令名，所以 `看看米雪儿` 会匹配失败。插件在 `QQListeners` 中拦截事件（早于命令分发），命中已知前缀后插入分隔空格，后续仍由框架统一执行（权限校验不变）。

注意：框架只对**插件主类实例**扫描 `@QQEventHandler`，因此独立监听器类需在 `onEnable()` 中手动 `QQEventManage.registerListener(...)`。

## 壁纸功能

```
壁纸          → 缩略图网格（9 张/页，带序号）
壁纸 3        → 第 3 张的 1920px 原图
壁纸 随机     → 随机一张
随机壁纸      → 同上（独立指令）
```

原图直接以 URL 交给 OneBot 的 `image` 消息，由客户端拉取，不占机器人带宽与磁盘。

数据来自 WIKI 的壁纸页，共 52 张（活动壁纸 48 · 移动端过场图 4），
均为 1920×1080。页面给出的是 889px 缩略图，原图地址由去掉 `/thumb/` 与尺寸后缀还原：

```
.../thumb/2/2b/<hash>.png/889px-<名称>.png
  → .../2/2b/<hash>.png
```

## 角色数据（dakanu.com/roles）

```
角色数据      → 角色胜率排行 + 地图攻防阵容
```

数据来自站点本地统计（约 12 万场排位对局），一张图包含两部分：

**角色胜率排行**：24 个超弦体的场次、胜率、登场率、日环比。
按胜率降序，带角色头像。

**地图阵容**：6 张地图攻防双方最常选的 5 个角色，右侧标注最热门角色的登场率。

### 两个数据处理上的取舍

**过滤小样本**。接口会返回只有 3-4 场的新角色（胜率偶然 75%）、
以及 `roleId=0` 的无效项。直接按胜率排序会让这些条目挤掉有参考价值的角色，
因此只保留 **1000 场以上**的样本（24 个）。

**不展示地图总胜率**。接口的 `mapStats[].winRate` 各图都在 69% 左右——
它实际是「防守方获胜率」，爆破模式防守天然占优，单独看没有区分度。
真正有价值的是攻防阵容，所以只展示阵容部分。

> 接口的 `sort` 参数不生效（三种排序返回完全相同），排序在客户端做。

## 奇点分

```
奇点分      → 文字说明 + 第 500 名高亮的排行榜
```

### 进入奇点的两个条件

```
① 超弦分达到 200 分
② 全服排名进入前 500 名
```

两个条件必须**同时满足**。因此当前「奇点分」就是第 500 名的超弦分，
但不低于 200：

| 第 500 名超弦分 | 奇点分 | 说明 |
| ---: | ---: | :--- |
| 350 | 350 | 超过门槛，取实际值 |
| 120 | 200 | 未达门槛，取保底 |
| 0（未进超弦） | 200 | 未产生超弦分，取保底 |

### 交互

1. **先发文字**：当前奇点分、两个条件、第 500 名的情况
2. **再发图片**：第 491-500 名，第 500 名红底高亮并标记「奇点线」

### 关于 score 字段

排行榜的 `score` 是**超弦分**，只有进入无限超弦（段位 29）才会计分。
榜单尾部玩家多为禁闭夸克（段位 26），其超弦分为 0 —— 这是站点规则，不是数据缺失。
图上分数位因此显示 `—`。

`/api/rankings/floor` 接口（站点算底分用的）当前返回 `current: null`，
所以奇点分改为直接从排行榜第 500 名读取。

## BGM 点播

曲目直链来自 WIKI（165 首，`patchwiki.biligame.com`），直接交给 OneBot 的 `record` 消息，由客户端拉取，不占机器人带宽。

```yaml
bgm:
  send-mode: "record"   # record（语音）或 link（直链）
```

**为什么有两种模式**：QQ 语音对时长与格式有硬限制（多数实现限制 60 秒内，部分客户端要求 silk/amr），而 WIKI 曲目普遍 2-5 分钟、约 5MB，直接发语音可能被拒绝或降级成文件。若你的 OneBot 支持长音频用 `record`，否则设 `link`。

## 图鉴与长内容

### 图鉴网格

装饰与素材类页面自动渲染成图标网格（36 个/页）：

| 指令 | 条目数 | 分页 |
| :--- | ---: | ---: |
| `勋章` | 404 | 12 |
| `喷漆` | 670 | 19 |
| `表情包` | 300 | 9 |
| `头像框` | 71 | 2 |

两种页面结构都能解析：

- `div.gallerygrid-item` + `span.badge`（装饰图鉴）
- `div.thumb` + `div.gallerytext > big`（表情包）

### 单张素材获取

网格类指令都支持按**名称**取单张原图（不是缩略图）：

```
表情包 得意       → 发 256×256 原图
表情包 喵         → 模糊匹配到「一问三不喵」
表情包            → 网格列表，36 个/页
表情包 2          → 第 2 页
```

列表用缩略图（加载快），单张查看用原图（更清晰）：

| 素材 | 列表缩略图 | 单张原图 |
| :--- | ---: | ---: |
| 表情包 | 180px | 256px |
| 勋章 | 见页面 | 256px |
| 头像框 | 见页面 | 636px |

原图地址由缩略图地址去掉 `/thumb/` 与尺寸后缀还原：

```
.../thumb/1/1a/<hash>.png/180px-表情_60000031.png
  → .../1/1a/<hash>.png
```

### 超长章节分段

章节超过 200 行时自动分段，用第二个参数指定：

```
勋章 2           → 提示共几段
勋章 2 1         → 第 2 章第 1 段
```

## 地图名称与编号

游戏对局的地图 ID 有**多套体系**，站点只为爆破模式提供了名称表：

| mapId 区间 | 模式 | 是否有名称 |
| :--- | :--- | :--- |
| 201-208 | 排位爆破 | 有，20 张完整名称表 |
| 200 | 排位爆破 | 无（`map-00.webp` 是 404 页面） |
| 405、414 | 团队 5v5v5 | 无 |
| 628-633 | 推车模式 | 无 |
| 3000 | 枪王模式 | 无 |
| 11001+ | 生化模式 | 无 |
| 16002 | 大头模式 | 无 |

### 显示策略

爆破模式正常显示地图名：`404基地`、`欧拉港口`、`风曳镇` …

其他模式没有官方名称，显示为「模式名 + 地图编号」，例如：

```
生化模式 地图 11002
排位爆破 地图 200
```

**不用「未知地图」**。这四个字容易让人以为程序出错，尤其容易和「404基地」混淆——
后者是正常地图名（mapId=201），前者只是没有数据。

### 缩略图只对爆破模式显示

站点按 `map-NN` 命名图片，`NN = mapId % 100`。但绝不能对所有 ID 套这个规则：

- `405 % 100 = 5`，指向 `map-05`（空间实验室）——那是**爆破模式**的图，团队模式用它是错的
- `11002 % 100 = 2`，指向 `map-02`（88区）——生化模式根本不是这张图
- `200 % 100 = 0`，`map-00.webp` 是 404 HTML 页面（548 字节）

因此只对 201-220 加载缩略图，其余显示占位色块。

## 已知限制

- **WIKI 是第三方数据源**，靠志愿者维护，可能滞后。每张图页脚都标注来源与原文链接。
